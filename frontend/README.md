# Team Work 前端

有兩種跑法，都在 `localhost:5173`：

- `make dev`：同時啟動前端和真正的[後端](../backend/README.md)，按 Ctrl+C 會一起關掉，其中一個停了另一個也會停；一開始沒有任何公司。後端連不上時畫面下方會提示，並自動重連。
- `make dev-mock`：用瀏覽器內的模擬器和假資料，不需要後端，任務會自己跑。

Mac App 使用 `make build` 建置，輸出為 `dist/Team Work.app`（未簽署，支援 Apple Silicon 與 Intel）。圖示來源是 `macos/AppIcon.iconset`，包含 16–512 pt 的 1×／2× PNG；建置時會轉成 `AppIcon.icns` 並放入 App。

接後端時，地圖上的位置和大樓外觀存在後端 SQLite，介面偏好存在 `preferences.yaml`；兩者都位於 `TEAM_WORK_HOME`（預設 `~/.team-work`），不匯入舊的瀏覽器設定；解散公司不會刪資料夾，所以沒有「同時刪除本地檔案」；ChatGPT 訂閱是真的登入。以下功能說明寫的是畫面，兩種跑法相同。

接後端時，可直接修改 `TEAM_WORK_HOME`（預設 `~/.team-work`）下的公司 YAML、員工 JSON、藍圖 YAML、任務藍圖 YAML、`provider.json` 與 `preferences.yaml`，再到「機場 → 設定 → 設定檔」按「重新載入設定」；同一區塊的「開啟設定檔資料夾」會在 Finder 打開這個位置。藍圖與流程可新增 YAML 檔匯入；新增公司、員工、供應商或刪除項目仍使用介面。驗證失敗會保留現有設定，有外部修改尚未載入時介面不會覆蓋檔案。任務、對話、記憶和憑證留在 SQLite。全域 `config.yaml` 修改需要重啟；格式見[後端說明](../backend/README.md#設定與儲存)。模擬模式沒有重新載入按鈕。

人像（走路、坐著辦公，坐姿不畫椅子，兩個平均分布、和其他欄位同寬），最右邊是骰子鈕，按一下會隨機換一套外觀（膚色、髮色、衣褲、配件、髮型與服裝款式），頭像和辦公室裡的人物都會跟著變。員工的詳細內容右上角有編輯鈕和解僱鈕（公司只剩一位員工時不能解僱）；解僱會再疊一張紙，列出他手上要交接的工作，選好接手的員工後按「交接並解僱」：他負責的任務、各任務藍圖與任務裡排給他的步驟、做到一半或還沒做的子任務都交給接手的人（做到一半的保留進度，等接手的人空下來接著做），之後他才離開公司。編輯鈕按下會在上面再疊一張編輯用的紙（每疊一張就往下錯開一段、底部不變所以矮一段：第一張靠左，第二張靠右貼近公司檔案，第三、四張落在這兩個位置之間的三分之一和三分之二處；所有紙一樣寬，底下每張紙露出來的地方都可以點，被蓋住的那張會稍微變暗；最多疊四張，再開就換掉最上面那張，第四張也不會蓋到右邊的公司檔案），和新增用的是同一張，可改名字、藍圖、模型、思考等級和外觀，按儲存才會生效；游標移到下面那張露出來的部分，那張紙會往左上稍微抽出來一點，移開就回位；點下去就是不儲存、收起上面那張回到下面那張。任務也一樣：任務頁籤列出使用者和員工建立的任務；由員工或對話建立的任務，詳細內容的標題下方寫著「由 誰 建立」（機場建立的寫機場服務人員）。每個任務都有一位「任務負責人」（一位員工），列在任務狀態旁，點了會疊上他的詳細內容；任務負責人對整個任務負責、合併時由他把分支合併回去，不會自動接手任何一步。任務的詳細內容在任務藍圖圖下方有「進度」和「紀錄」：「進度」依開始的順序列出每一個子任務，每列開頭是員工頭像和該步驟的便條紙，還沒完成的在下面顯示進度條或狀態（等人接手、等其他前一步完成）；需要使用者回覆的（員工有問題要問、拿不定要交給哪一步、重試用完、任務費用到上限、開會討論）只寫狀態，右邊有紅色圓形加白色驚嘆號，這時任務在「待回覆」欄，要點那一列打開子任務才能回覆：子任務的「等你回覆」寫出員工的完整訊息，下面有選項（可選一個，再點一次取消）、回覆框和「確認」：有問題要問時可以只寫回覆不選選項，其他情況要選一個，回覆寫進員工的記憶，送出後任務繼續；完成的則是交接摘要，退回的那幾次以紅字寫出退回給誰和原因，重做的步驟會標「重做」，點一列會疊上那個子任務。任務說明、員工的回覆和問題、對話與討論、交接內容、`.md` 檔案和紀錄裡員工說的話都以 Markdown 顯示（表格、清單、程式碼等；不執行 HTML、不載入外部圖片，網址連結開在外部瀏覽器）；使用者自己打的對話照原樣顯示，其他檔案照原文顯示。任務和子任務的「紀錄」裡，使用者自己的回覆、合併和退回前面會加上綠色粗體的「使用者」。點一個子任務會再疊一張，寫著負責員工（點了會再疊一張那位員工的資料）、接自哪一步、交給（或退回給）哪一步、被誰退回、花費、交接摘要和它自己的紀錄；交接裡列出的檔案點了會再疊一張，顯示那次 commit 裡的檔案原文（`make dev-mock` 則是假資料），內容寫在一張略微歪斜的白底便利貼上；PNG、JPEG、GIF、WebP 圖片直接顯示圖片（上限 25 MB）；檔案不在那次 commit 裡、太大（超過 1 MB）或不是文字檔時，便利貼上會寫明原因；交接裡不是單一檔案的項目只顯示文字，不能點。任務卡片右下角寫著消耗的 Token 數（還沒消耗時不顯示），左邊用淡色字寫進度：目前的步驟名稱和「完成步驟數/流程總步驟數」，例如「審查 · 3/6」（有幾個步驟同時進行時寫「審查 +1」，名稱太長時先截斷；負責人主導的任務，步驟要等負責人接受才算完成，被退回作廢的不算）；待辦和完成的任務不顯示，等待合併時寫「6/6」。任務說明寫在一張略微歪斜的白底便利貼上，位置在「進度」和「紀錄」之間。任務的詳細內容在標題下方以等寬字寫出任務分支（`task/編號`，前面有分支圖示）。任務的詳細內容右上角有編輯、複製、開始／暫停（新任務建立後留在待辦，狀態寫「待辦」而不是「已暫停」，按開始才開工；開工後變成暫停，暫停後變成繼續）和刪除：複製會疊上一張新任務，標題、說明、附圖、任務藍圖、任務負責人和每一步的員工都帶入原任務的內容（已離開的員工不帶入，任務藍圖已刪除時改用公司的預設），按「建立任務」才會建立；編輯和新增時都能按任務負責人右邊的「套用到所有節點」，讓每一步都只由任務負責人執行；編輯可改標題、說明、任務負責人和每一步的負責員工，負責人主導的任務在待辦、進行中（含暫停）和等待合併時，還能用和新增任務自訂流程同一套編輯器直接改流程（拖曳連線、插入、新增、刪除步驟，點便條紙改種類、名稱、Prompt、開始條件、交接和人員），已經執行過的步驟畫成淡灰色、沒有垃圾桶；改了步驟或連線的任務流程名稱加上「（自訂）」、不再對應任務藍圖，等待合併時改流程會回到進行中；打開編輯單之後負責人又調整了計畫時，儲存會被拒絕並保留表單內容；刪除要再按一次「確定刪除」才會執行。步驟有兩種：「員工執行」（白色便條紙）和「開會討論」（綠色便條紙）。以下討論操作僅適用於舊制（Legacy）任務：開會討論的指示固定（談到下一步可以直接動手為止，每次回覆都整理結論和驗收條件），不能修改；它和工作一樣在新增任務時指定員工：工作步驟只能有一位；討論步驟排一位是單人討論，排多位（最多 6 位）是會議，第一位是主持人，由他開場，你用 @ 提及的人依序回話，@All 是所有人、主持人最後，沒提及任何人時由主持人回話，每則回覆前面是說話者的頭像；輪到它時，員工讀完前面的交接後在子任務裡開一個聊天框問你問題，你們可以來回討論多輪（Enter 送出、Shift+Enter 換行，員工回覆時會先顯示「···」，接著逐字顯示內容，回完才能再送），談定後按「結束討論」選：「繼續」把討論結果交給下一步（這一步的交接是「交給其中一個下一步」時改成每個下一步一個按鈕），「退回」寫下原因把前一層的步驟退回重做，重做完會再開一次討論，或「停止任務」（要再按一次「確定停止任務」）把整個任務停掉。在舊制討論裡，你說過的話會寫進員工的記憶和交接裡。負責人主導的任務則不同：負責人召集的會議和流程裡的討論步驟，都直接在任務主留言區進行，由負責人主持，加上 1 到 6 位員工；你可以隨時插話，用 `@` 指定與會員工依序回答，沒有指定時由負責人回答。與會員工只能讀，不能改檔案、交接或改記憶。你按「結束開會」或負責人用工具結束時，由負責人寫結論；結束後會議收成一塊，結論露在外面，可展開看全部發言。詳見[任務功能說明](../README-tw.md#功能)及介面「使用說明 → 任務」。任務藍圖沒有固定的頭尾：沒有箭頭指進來的步驟都是起點，任務開始時同時開工、各自直接拿到任務說明；沒有箭頭指出去的是終點；新建的任務藍圖只有一個空白步驟。只有一個前一步、且那一步只交給它的工作步驟都可以退回（不用另外設定，任務藍圖的詳細內容會寫出哪幾步可以）：做完時覺得前一步要重做就把工作退回去（盡量由原本的員工），重做完照原本的方向再交下去；起點和討論步驟不能退回；退回不會取消其他支線；一個任務最多退回兩次。每個任務有自己的 work tree：第一個步驟開工時從目標分支開出任務分支（`task/編號`），之後每一步的員工都 commit 到這個 work tree，若別人在他做事時先 commit 了，他會先合進對方的 commit、解完衝突再 commit。所有實際開工的支線都做完後（條件分支沒選到的步驟不用等）任務進入「待回覆」，「進度」最下方多一列任務負責人的「合併」：寫著任務分支 → 目標分支，這一列點了不會展開，同一列最右邊是紅色的「合併」和白色的「退回」；按合併後任務回到「進行中」（卡片上標「合併中」），由任務負責人把 work tree 合併回目標分支，有衝突時先解衝突，完成後移除 work tree、任務變成完成；按退回會出現文字框，填寫要改什麼後送出，工作退回給最後完成的終點的前一步重做，退回原因以紅字記在進度裡。任務藍圖也是：任務藍圖的詳細內容在任務藍圖圖下方依任務藍圖順序列出每個步驟的 Prompt 和交接方式，每一步整個寫在一張便條紙上，顏色和任務藍圖圖上的一樣（工作白色、開會討論綠色），新增和編輯任務藍圖時的步驟列表也是，點圖上的便條紙會捲到那一步。機場設定的任務藍圖頁籤最上方有「＋ 新增任務藍圖」，任務藍圖的詳細內容右上角有編輯、複製和刪除（複製會直接建立一條叫「原名稱-1」的新任務藍圖，名稱已被用掉就往下編號；刪除同樣要再按一次「確定刪除」；只剩一條任務藍圖時不能刪，刪掉某間公司的預設時，它會改用另一條（已經開始的任務照原本的任務藍圖繼續）。新增和編輯任務藍圖用同一張紙：填名稱，任務藍圖圖下方列出每個步驟，直接在這張紙上改種類（員工執行或開會討論）、名稱、Prompt（開會討論沒有這一欄）、開始條件、交接（交給其中一個下一步或交給所有下一步）和下一步，每一步旁有刪除（只剩一步時沒有），點便條紙會捲到並選取該步驟的名稱；任務藍圖圖上下留有較多空白，「＋ 新增步驟」是滿版的虛線框，只有一個終點時把新步驟接在它後面，否則新步驟單獨成為新的起點，新步驟依序命名為「新步驟1」「新步驟2」…（取第一個還沒被用的數字）；新增的步驟不會自動跳到列表，點它的便條紙才會跳過去；游標移到便條紙上（只剩一步時沒有），右上角會出現垃圾桶，點一下變成「確定刪除」，再點一下才刪掉這一步（滑鼠移開或點別處就取消）（按儲存前都不算數）；步驟之間的箭頭可以直接在任務藍圖圖上改：按住便條紙拖到另一張便條紙就接上（拖的時候接不過去的步驟會變淡，不能繞回去），拖到任務藍圖圖的空白處放開就從這一步長出一個新的下一步，拖到任務藍圖圖外放開則什麼都不做；箭頭中間的小圓點在游標移上去時展開成「＋」和「×」，分別是在這條箭頭上插入新步驟和拿掉這條箭頭；跳過一步的箭頭會從上方繞過去；有步驟沒有名稱時不能儲存。待辦欄最上方的「＋ 新增任務」會貼上一張新任務：填標題、說明、附圖（按虛線框的「＋」選圖片，或在標題、說明的文字框直接貼上截圖，每張縮圖右上角的 × 可移除；建立後在任務的詳細內容說明下方列出縮圖，點了會疊一張看原圖）、選任務藍圖和任務負責人（預設沿用上一個任務的負責人；只能選一位；選員工和選藍圖的下拉選單直接在選單內列出圖像、模型或來源和工具便利貼，員工依藍圖分組），下方的任務藍圖圖每個步驟下排著這次的負責員工，預設沿用同一條任務藍圖上一個任務的配置；點便條紙會疊一張員工名單，可勾選多人，同一人也可負責多步，按確定才會改；沒有人的步驟右上角會有紅色圓形驚嘆號；有任務負責人、每一步都有人、也有標題後才能按「建立任務」。任務的詳細內容也會畫出這次的人員配置，已經做完的步驟變成淡灰色；點這張任務藍圖圖會疊一張任務藍圖圖加上每個步驟的列表（每一步整個寫在便條紙上，做完的步驟和圖上一樣變成淡灰色），點圖上的便條紙會捲到列表裡的那一步並短暫標出，列表裡的員工點了會疊上他的詳細內容，員工的詳細內容則列出他在進行中任務裡負責的步驟。檔案打開時像報紙貼上牆，關閉時反過來，從牆上撕起淡出；物件和名牌出現時從透明淡入，消失時淡出，物件的陰影也跟著漸漸變濃或變淡（低空雲的影子也是）。打開時地圖不能平移縮放；沒有關閉鈕，點地圖其他地方（包括打開的辦公室本身）收起（鍵盤可按 Esc），鏡頭回到打開前的位置。

島上民眾與辦公室員工共用 `avoid.ts` 的避碰：舒適間距與身體碰撞分開，移動、側移、推開時都檢查整段路徑；坐著與淡入淡出中的人也佔位置。站著聊天或發呆的人擋路時，會中斷活動、走到附近安全空位讓行；坐著或正要回座位工作的人不會被當作閒站者趕走。直窄道前遇到迎面來人時，優先讓已在窄道內的人通過，同時抵達則依固定順序退到通行路線外等候；看不到轉角另一側或沒有安全退路時，仍使用近距離繞路、等候或取消活動，回座位會稍後重試，不會暫時穿過別人。共用大門有人接近要進入時，屋內的人先等候，門內外有空位才出門。出發時計入沿途人潮，優先選較清靜的走法；散步在寬敞路段加入依人物固定的小幅彎路，回座位不加散步彎路，座位與門口的接近位置不變。側身避讓同一個人時保持方向，不每次更新左右換邊。身體用水平圓形範圍近似（辦公室直徑 0.64，島上 0.96），不是每根手指、揮手或帽子的逐面碰撞；不保證任意擁擠佈局都能到達目的地。

## 執行

在專案根目錄執行：

```sh
make dev
```

首次執行會安裝套件。開啟 http://localhost:5173。資料存在 `~/.team-work-dev`（和 Mac App 的 `~/.team-work` 分開），要用別的資料夾就設定 `TEAM_WORK_HOME`。

`make dev-mock` 是前端假資料模擬，不執行 Agent、不操作 Git。重新整理會重設模擬，不保存修改。

長對話開啟時先顯示最新 100 則訊息（包含工具紀錄），在頂端按「顯示更早訊息」每次再展開 100 則，保留原本閱讀位置。新回覆不會隱藏已展開的訊息；重新開啟或切換對話回到最新一批。未展開的歷史暫時不在頁面中，瀏覽器搜尋與文字選取只能涵蓋已顯示內容；正式模式啟動與重連只接收摘要，開啟對話才分頁讀取，關閉後釋放該畫面的歷史；模擬器與舊後端仍使用全文資料並分批繪製。完整歷史留在後端，不會刪除。

## 檢查與建置

```sh
npm --prefix frontend test           # 模擬器與城鎮版面測試
npm --prefix frontend run typecheck  # 型別檢查
npm --prefix frontend run build      # 建置到 frontend/dist/
npm --prefix frontend run preview    # 預覽建置結果，port 5173
```

`src/` 底下是畫面與樣式；`src/core/` 是公司資料的模擬器（領域模型、假資料、執行模擬）。

three.js 的建置檔較大，建置時可能出現超過 500 kB 的提醒。

正式模式的 `world` 只隨資料變動更新，不隨時鐘跳動；需要經過時間的畫面用 `core/store.ts` 的 `useNow()`，每秒更新自己的顯示。模擬模式仍由 `useSimLoop()` 每秒推進十次，`useNow()` 讀取模擬時間。

對話閒置效能回歸檢查：先用 `npm --prefix frontend run dev` 啟動非 mock 的 Vite（不需後端），再於根目錄執行：

```sh
PERF_TOOLS=/path/to/playwright node scripts/chat-perf.mjs http://127.0.0.1:5173 300
```

`PERF_TOOLS` 指向已有 `playwright-core` 與 Chromium 的工具套件目錄，不會自動安裝。腳本只接受本機網址，用合成訊息掛載實際 `ChatSheet`，攔截 API 與 WebSocket，不讀正式資料、不呼叫模型。它量測閒置三秒的 React 更新次數、主執行緒工作時間與 JS 堆積，並檢查輸入草稿、串流、分批展開的捲動位置、原始訊息操作索引、切換對話及截斷歷史；閒置更新次數不是零會失敗。這是開發版隔離頁面，非正式 App 的 CPU 或實體記憶體量測。比較版本時請重新啟動 Vite，避免熱更新模組影響結果。

### 聲音

「機場 → 設定」的「音樂」區塊最前面是「背景執行時靜音」（預設勾選）：視窗失去焦點或頁面被隱藏時停止音樂和音效，回來後繼續；取消勾選後會繼續播放，不過畫面在背景時地圖動畫可能被瀏覽器暫停，飛機音效也就不一定會響。同一區塊可分開調整背景音樂與音效（0–100%，0 為靜音），兩個拉桿右邊各有「靜音」勾選框，勾選後立刻靜音、取消後回到原音量，並獨立開關、試聽飛機音效（起飛、降落、飛越合併為一個開關）、介面操作、通知音效與打開建築音效（打開公司是約 0.36 秒、由左往右的輕柔帶通噪音「唰」；打開機場是 C5、E5、G5、C6 四個上行的柔和顫音琴音，前面先留 350ms 空白，間隔 260ms，共約 2.95 秒；兩者共用一個開關，不壓低其他聲音）。「海浪」是島周圍的海聲，開啟時持續循環播放：低沉不斷的涌浪底層，加上 26 秒循環裡五道間隔不一、會湧起、拍岸再退去的浪；它的音量是音效音量的 20%、跟音樂疊在一起，通知響時一樣暫降，因為開著就聽得到，沒有試聽按鈕。背景音樂預設 50%、音效預設 100%，個別音效（含海浪）皆開啟。「機場 → 設定 → 音樂」可選輕快波莎（預設）、復古遊戲、輕柔鋼琴或空靈氛圍，切換時以 1.2 秒交叉淡入淡出；四首各有自己的調性、拍號與編制，都是由程式合成的原創立體聲循環（40 秒以上），選擇會共用儲存。有任務新進入待回覆或待合併，或員工回覆完、對話變成未讀（該對話沒開著）時，會播放一低一高兩聲冒泡音（C5、G5，間隔 130ms，每聲音高在約 40ms 內上升 70%），約 0.5 秒。飛機音效的音量為音效音量的 60%，由引擎呼嘯、渦輪聲與輪胎聲組成並在左右聲道間移動：起飛在拉起時最響，降落在觸地時有輪胎摩擦聲、接著是反推力，飛越在頭頂時最響且音高下降；介面操作是紙張壓下的雙層清脆聲，帶一點柔和低音，音高每次略有變化；通知前 40ms 先壓低其他聲音，通知播放期間，所有其他音效與音樂暫降至各自音量的 40%，結束後依最新設定恢復（保持靜音的項目不會被打開），不因頁面更新、初次載入或重連而補播既有通知；同批多則通知只響一次。「聲音」中的「通知」可獨立關閉。飛機音效與動畫時機同步；關閉飛機動畫或啟用減少動態時不會自動播放飛機音效，仍可手動試聽。第一次點擊或按鍵後才啟動聲音，頁面隱藏時暫停，返回時恢復音樂，不補播錯過的音效。聲音設定和其他偏好一樣共用 `preferences.yaml`；mock 模式只存在記憶體。音樂與音效由 `src/soundSynth.ts` 合成成樣本，再用 Web Audio API 播放，不下載外部音檔。

飛機音效開關會一次儲存起飛、降落與飛越三個既有偏好欄位；舊設定若只有部分開啟，合併開關仍顯示已勾選；取消會全部靜音，重新勾選則全部開啟。

啟動時先顯示一片純藍的啟動畫面（`public/boot/`，Mac App 在後端啟動期間顯示相同畫面），等地圖畫好才淡出，鏡頭跟著一架飛機在高空飛過海面和稀疏的雲（從比遊戲視角更陡的斜上方往下看），飛機一開始畫得比較大、隨鏡頭下降縮回原本大小，影子要飛到島的上空才淡入；小島從畫面邊緣出現的那一刻起，一邊隨鏡頭下降慢慢變大、一邊轉成遊戲的斜角，最後停在島上，飛機繼續飛出畫面才消失，這時按鈕和面板才從各自所在的畫面邊緣外滑入、公司名牌淡入（`src/Voyage.tsx`，路線計算在 `src/voyagePath.ts`）：第一次執行完整播放，之後縮短（記錄在瀏覽器的 `localStorage`），任何點擊、滾輪或按鍵都會直接跳到結束。啟用減少動態時只淡出，鏡頭不動。後端連不上時下方顯示提示並自動重連。透過基地台前往別台的島或回到自己的島時，按鈕和開著的面板先滑出到各自所在的畫面邊緣外、公司名牌淡出，接著一架飛機從目前小島的機場起飛（機場自己那架如果正在跑道上會先淡出讓開），鏡頭跟著爬升、轉成較陡的斜上方視角，飛機離開島的上空時影子淡出。去別台的島時飛機一路往畫面右邊飛，回自己的島時一起飛就迴轉往左飛；等舊島完全離開畫面才換島，飛機繼續往同一邊直飛；等新島的資料和每間公司的專案大小都讀到（最多等 15 秒），飛機和鏡頭悄悄移到新島前方的海上（海面紋路和雲跟著移，看不出跳動），新島從飛機前進的那一側出現，飛機飛越小島、從另一側飛出畫面，鏡頭用同樣的方式降落，介面再從畫面外滑入（飛行途中新出現的介面也先待在畫面外，跟著一起滑入），不會先只看到機場和基地台、建築物晚幾秒才出現。飛行途中無法操作地圖；任何點擊、滾輪或按鍵會跳到結束，起飛中則直接換島、飛到海上。啟用減少動態時改成雲層和像素字標（素材在 `public/boot/`）從四周聚攏蓋住地圖（淡入），蓋滿後換島，等新島畫好後雲才散開。
