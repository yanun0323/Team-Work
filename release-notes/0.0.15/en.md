## What's new

**Tasks are written with the right expectations**
- When someone writes a task, they're now told how a task actually runs: it works on its own copy of the project, starting from the latest commit, saves its work at each hand-off, and you decide when to merge it.
- So chat habits like "only commit when asked" no longer sneak into task descriptions.
- Each step also knows that ignored files, like installed dependencies and `.env`, aren't in its copy, so it won't go looking for them.
